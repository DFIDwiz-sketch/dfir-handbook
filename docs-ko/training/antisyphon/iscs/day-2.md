# Day 2 — 나가는 트래픽 분석 { #day-2 }

<div class="dfir-meta" markdown>
**과정:** Information Security Core Skills · **강사:** John Strand (BHIS) · **2일차 범위(지금까지):** Egress 트래픽 분석 → NetFlow → 방화벽 로그 분석 → Zeek → 비컨 → RITA
</div>

!!! abstract "2일차 한눈에 (1~2부)"
    1일차가 "들어오는 것을 막는" 이야기였다면, 2일차는 **이미 들어온 공격자를 어떻게 찾는가**입니다. 핵심은 **밖으로 나가는 트래픽(egress)** — 감염된 PC가 C2 서버와 주고받는 통신입니다. 내용은 암호화돼 못 봐도 **행동 패턴**(규칙적 간격 + 일정한 크기 = **비컨**)은 보입니다. **Zeek**로 트래픽을 일관된 메타데이터 로그로 만들고, **RITA**로 그 로그에서 비컨을 수학으로 찾아냅니다.

!!! info "이 페이지는 진행 중입니다"
    현재 **1~2부**(Egress·NetFlow·수동 로그 분석·Zeek·비컨·RITA)까지 정리되어 있습니다. 3~5부(AC-Hunter 실습·ASN/차단 목록·UEBA·Deep Blue CLI·Sysmon)는 이어서 추가합니다.

!!! note "표기 규칙"
    **💡 보충 (강의 외)** = 강의에 없던 제 추가 설명. **(재구성)** = 강사가 화면으로만 보여 줘 제가 복원한 명령어이므로 실제 실습 안내문 기준으로 쓰세요.

## 1. 왜 "나가는 트래픽(Egress)"인가? { #why-egress }

공격자가 PC를 장악하면 그 PC는 공격자의 **C2 서버(명령·제어 서버)**와 계속 통신합니다. 이 통신은 **안에서 밖으로** 나갑니다(1일차의 reverse connection). 그래서 나가는 트래픽을 보면 감염된 내부 PC를 찾을 수 있습니다. MITRE ATT&CK에서 C2·흔한 포트 사용·데이터 반출은 많은 조직이 놓치는 영역입니다.

놓치는 이유는 **암호화**입니다. 요즘 트래픽은 대부분 TLS/SSL이라 내용을 못 봅니다. TLS를 중간에서 복호화하는 장비도 있지만 사생활·GDPR 문제가 생깁니다.

!!! quote ""
    "암호화돼서 못 본다"는 변명은 통하지 않는다. 내용을 못 봐도 **행동 패턴(behavior)**은 볼 수 있다.

## 2. NetFlow — 연결 통계 { #netflow }

내용을 못 봐도 **"누가·누구와·언제·얼마나" 연결했는지**는 볼 수 있습니다. 이것이 **NetFlow**(Cisco가 만든 연결 통계)입니다.

- **Exporter(내보내는 장치)** — 연결 데이터를 보내는 장비(라우터·방화벽)
- **Importer/Collector(수집기)** — 그 데이터를 모으는 곳
- **Analysis engine(분석 엔진)** — 모인 데이터를 분석해 의미를 뽑는 곳

NetFlow가 표준이 되자 sFlow·jFlow·NetStream 등 비슷한 것들이 쏟아졌습니다 — 모두 "연결 통계를 다루는 서로 다른 방식"입니다.

## 3. 실습 — Cisco ASA 방화벽 로그를 손으로 분석 { #asa-lab }

John은 먼저 **"손으로 하면 얼마나 괴로운지"**를 보여 줍니다. 전제: 어떤 내부 IP가 감염됐다고 **가정**합니다(여기서는 `192.168.1.6`).

```bash
sudo su -
cd /opt/firewall_log
grep 192.168.1.6 <로그파일>        # (재구성) 그 IP가 든 줄만 추출
```

- `grep <문자열>` = 특정 문자열이 든 줄만 골라내는 명령.

로그는 지저분합니다(John 표현으로 "악몽"). 데이터를 조금씩 다듬어 통계를 뽑을 형태로 만든 뒤, **R tools**라는 도구 모음으로 수학 분석을 해 **비컨**을 찾습니다. 요점은 "손으로도 되지만 너무 힘들다 → 그래서 Zeek·RITA가 필요하다".

## 4. AI로 로그 분석 — 맥락이 핵심 { #ai-log-analysis }

같은 ASA 로그를 ChatGPT에 넣어 봅니다.

**① 그냥 "나쁜 트래픽 찾아줘"라고 하면** → AI가 **엉뚱한 것**(포트 스캔처럼 보이는 것, Telnet, ACL 차단 등)을 지목하고 **진짜 악성 비컨은 못 찾습니다**. **맥락(context)**을 모르면 **헛다리(hallucination)**를 짚기 쉽습니다.

**② 맥락을 주면** (내부/외부 IP, 제외할 주소, 완료된 연결만 — 백도어가 두 외부 IP를 번갈아 씀) → 훨씬 가까워지지만 "정상 같다"고 **잘못 결론**내기도 합니다. 결정적 단서는 **시각**입니다.

```text
1초, 1초, 1초, 1초, 1초 …   (완전한 TCP 연결/종료가 매초 반복)
```

> 원격 터미널·keep-alive가 아닌 이상, 매초 완전한 TCP 연결·종료를 반복하는 정상 서비스는 거의 없다 → **악성 비컨**.

R tools로 확인하면:

```text
최소 1816, 최대 1848, 평균 1829, 표준편차 12
```

**표준편차(standard deviation) 12**는 아주 작습니다 — 데이터 크기가 거의 일정하다는 뜻으로, **비컨의 전형적 특징**입니다.

!!! tip "AI 시대의 핵심 역량"
    "나쁜 것 찾아줘"는 잘 안 통합니다. 배운 지식으로 **질문을 좁혀 줘야** 좋은 답이 나옵니다. "로그를 어떻게 분석할지 아는 것"과 "올바른 질문을 던지는 것"이 핵심입니다.

## 5. Zeek — 일관되게, 작게 { #zeek }

손 분석이 괴로우니 **Zeek**(예전 이름 Bro)를 씁니다. 빠르고, 사용자 기반이 크고, **타임스탬프가 완벽히 일관적**입니다(장비마다 시각을 제각각 다루는데 Zeek는 흔들림 없음).

여기서 사고의 전환이 있습니다. 1일차 백신은 실행 파일 안 **문자열(어셈블리)**을 찾는 시그니처 방식이었지만, 트래픽은 **암호화**돼 문자열을 못 봅니다. 대신 **로그의 행동 패턴**을 보면 공격자를 능동적으로 **사냥(hunting)**할 수 있습니다. 앞으로 더 중요해지는 이유는 **AI** — 악성코드·새 C2·난독화를 AI가 만들 수 있으니, **사람이 AI를 써서 트래픽 패턴을 사냥**해야 합니다.

**Zeek vs 전체 패킷(full PCAP)**

| | 전체 PCAP | Zeek |
|---|---|---|
| 장점 | 모든 내용, 모든 도구 지원(이식성 최고) | 크기 약 **1/10** |
| 단점 | **너무 큼** | 원본 패킷 내용 없음(메타데이터) |

Zeek는 패킷을 압축하는 게 아니라 **메타데이터**로 바꿔 크기를 1/10로 줄입니다.

!!! warning "NAT 앞단(pre-NAT)에서 잡아라"
    방화벽 바깥(인터넷 쪽)에서 보면 모든 내부 PC가 **방화벽 하나의 IP로** 보여 감염된 PC를 특정할 수 없습니다. **NAT 앞(내부 쪽)**에서 잡아야 **감염된 내부 사설 IP**를 알 수 있습니다.

Zeek 로그 자체(`conn.log`, `dns.log`, `http.log`, `ssl.log` 등)는 [네트워크 → Zeek](../../../network/zeek/index.md)에 정리되어 있습니다.

## 6. 비컨(Beaconing)이란? { #beaconing }

John의 비유: 아이가 "엄마, 엄마, 엄마…" 하고 **일정하게 반복**하는 것이 비컨입니다. 감염된 PC가 C2에게 "저 여기 있어요, 명령 주세요"를 규칙적으로 반복하는 것. 세 가지로 분석합니다.

1. **간격(interval)** — 심장박동처럼 규칙적인가
2. **데이터 크기** — 매번 거의 같은가(표준편차가 작은가)
3. **연결 시각** — 완료·재시작이 좁은 간격으로 반복되는가

**지터(Jitter)** — 영리한 공격자는 간격을 일부러 **흔듭니다**(예: 7초 ±2초 → 5~9초 랜덤). 완벽히 규칙적이진 않아도 **여전히 비컨의 특성**(7초를 중심으로 대칭적으로 모임)을 가집니다. **간격이 완벽할 필요는 없고, 비컨의 특성만 있으면 됩니다.**

**롱 커넥션(Long Connection)** — 비컨 말고, 연결 하나를 **아주 오래 붙잡는** 방식도 있습니다. John의 스파게티 비유: 긴 한 가닥(긴 연결)을 뚝뚝 부러뜨리면 조각들이 되지만(쪼개진 연결), **다 모으면** 원래 하루치가 됩니다. 쪼개서 숨겨도 **총합을 보면** 드러납니다.

전체 비컨·C2 탐지 정리는 [네트워크 → 비컨 & C2](../../../network/beaconing-c2.md).

## 7. RITA — 비컨 탐지 엔진 { #rita }

이 분석의 수학은 **RITA(Real Intelligence Threat Analytics)**에 들어 있습니다. BHIS가 만든 **무료** 도구이며, 특허로 오픈소스를 유지합니다. 하는 일은 둘 — **비컨 찾기**와 **차단 목록(deny list) 대조**(알려진 나쁜 IP와 비교, 3부에서 자세히).

**어떤 수학을 쓰나**

- **K-means 클러스터링** — 데이터에서 **패턴(일관성)**을 찾는 알고리즘. CAPTCHA가 "신호등/자전거를 모두 고르세요"를 반복시켜 패턴 인식을 학습시키는 것과 같은 원리로, **일정한 간격·크기로 뭉친 덩어리**를 찾습니다.
- **MADM (평균 절대 편차)** — 비슷하게 분포의 일관성을 봅니다.

**비컨 점수(score)** — 각 연결에 **0~1 점수**를 매기고, **1에 가까울수록 완벽한 비컨**입니다. **연결 수**도 함께 봅니다(예: 완벽한 간격으로 108,000번 연결).

!!! warning "비컨 = 꼭 악성은 아니다 (정상 비컨들)"
    규칙적으로 비컨하는 것이 악성코드만은 아닙니다 — **TeamViewer**(직원이 필터 우회용으로 쓸 수 있음), **RDP**, **Nuance/Dragon**(원격 제어 기능 내장 사례), **LAN Turtle**(USB-이더넷 모양 소형 리눅스). 전부 악성은 아니지만 **전부 조사할 가치**가 있습니다.

**그 밖에 볼 수 있는 것** — **User-Agent 문자열**(내부 시스템이 자신을 어떻게 소개하는지), **MIME 타입**(오가는 데이터 종류 — 3부 "MIME 불일치"로 재등장), **JA3/JA4**(TLS client hello로 클라이언트 지문 인식; JA3는 브라우저 랜덤화로 깨져 지금은 JA4).

**롱테일 분석(Long-tail analysis)** — 정상 vs 비정상을 정렬하면 **드문 꼬리(long tail)** 쪽에 이상 징후가 모입니다. 사람 트래픽은 지저분하고 불규칙한데 **비컨은 유난히 일관적**이라 꼬리에서 튀어 보입니다.

### 강의에서 RITA를 직접 실습하나? { #rita-lab-note }

**2일차에는 RITA를 명령줄로 직접 돌리는 독립 실습은 없습니다.** RITA는 "엔진(원리)"으로 설명하고, 실제 손으로 하는 비컨 분석은 그 엔진을 얹은 **AC-Hunter의 GUI**로 합니다(3부). 즉 **RITA = 무료 명령줄 엔진**, **AC-Hunter = 그 위의 유료 GUI**(커뮤니티 에디션 있음). 처음 ASA 로그 실습의 비컨 수학은 RITA가 아니라 **R tools**로 했습니다.

!!! note "💡 보충 (강의 외) — RITA 직접 돌려 보기"
    RITA는 무료이므로 홈 랩의 Zeek 로그로 직접 돌려 볼 수 있습니다(개념 흐름).

    ```bash
    # Zeek 로그를 RITA 데이터베이스로 가져오기
    rita import /opt/zeek/logs/2026-10-17 mydataset
    # 비컨 분석 결과 보기 (점수 높은 순)
    rita show-beacons mydataset
    # 차단 목록 매칭 등
    rita show-exploded-dns mydataset
    ```

    `rita import <Zeek 로그 폴더> <이름>`으로 로그를 적재하고, `rita show-beacons <이름>`으로 비컨 점수(0~1)와 연결 수를 봅니다. 최신 RITA(v5+)는 설정이 조금 다르니 공식 문서를 확인하세요. 실제 강의 실습과는 별개인 **보충 실습**입니다.

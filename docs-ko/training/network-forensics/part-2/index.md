# 2부 — 핵심 프로토콜과 로그 집계·분석 { #part-2 }

!!! abstract "2부에서 다루는 것"
    거의 모든 사건에 등장하는 두 프로토콜, HTTP와 DNS를 조사자의 눈으로 읽는 법부터 시작합니다. 요청과 응답의 각 부분, 웹 서버 로그, DNS의 구조와 악용 방식(빠른 플럭스, 도메인 생성 알고리즘, 암호화 DNS)을 다룬 뒤, Zeek로 패킷을 로그로 바꾸고 jq로 다룹니다. 마지막으로 syslog와 Windows 이벤트 로그를 한곳에 모으는 로그 집계와 Elastic Stack 기반의 분석 환경을 익힙니다.

## 2부를 마치며 { #wrap-up }

2부를 마치면 다음을 할 수 있어야 합니다.

- HTTP 요청과 응답의 각 부분(메서드, 헤더, 상태 코드, 쿠키)을 조사자의 눈으로 읽고, HTTP/2·HTTP/3에서 무엇이 보이고 무엇이 안 보이는지 안다(2.1~2.3강).
- 헤더 조합, 시간대, 간격으로 사람과 프로그램을 가르고, 광고 쿠키로 증거 기간 너머를 본다(2.4강).
- 웹 서버 로그의 형식과 함정(받은 시각, 크기 필드, 이스케이프)을 알고 공격의 흔적을 찾는다(2.5강).
- DNS의 메시지, 압축, 계층, 캐시를 이해하고, 관측 지점에 따라 보이는 것이 다르다는 점을 고려해 빠른 플럭스, DGA, 터널링, 암호화 DNS, 닮은꼴 도메인을 찾는다(2.6~2.7강, 2.9강).
- Zeek로 pcap을 로그로 바꾸고, jq로 고르고 잇고, Community ID로 도구 사이를 오간다(2.8강).
- syslog와 Windows 이벤트 로그의 형식, 시각, 전송의 한계를 알고, 중앙 집계의 사본으로 지워진 흔적을 찾는다(2.10~2.12강).
- Elastic Stack(SOF-ELK)에 여러 출처를 넣고, 넣은 만큼 들어왔는지·시간대가 맞는지 확인한 뒤, 하나의 단서로 사건 전체를 엮는다(2.13~2.14강).

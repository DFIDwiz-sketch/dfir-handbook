# 품질 관리와 사건 검토 { #quality-review }

!!! abstract "한 줄 요약"
    앞 섹션들은 경보 하나를 확인된 침해와 대응 방식 선택까지 끌고 왔습니다. 이 섹션은 **잘 마무리하고 더 나아지는 법**을 다룹니다. 모두가 속도만 볼 때 왜 품질에는 글로 쓴 기준이 필요한지, 좋은 사건 기록은 어떤 모습인지, 닫기 전에 킬 체인을 다시 맞추기, 닫은 사건을 분류해서 지표와 위협 인텔리전스로 바꾸기, 귀속에 대해 정직하기 — 그리고 도전 분석 기법(사전 부검, 구조화된 자기 비판, What If?, 레드팀과 Team A/B 분석)과, 이를 새 분석 규칙·지표·인텔리전스로 이어지는 정기적이고 부담 없는 동료 검토로 만드는 법을 봅니다.

## 꼭 기억할 것 { #must-know }

1. 속도는 보이고 품질은 안 보인다. 잘 처리된 사건의 모습을 글로 쓰고, 그것과 대 본다.
2. 팀 공용 종결 체크리스트를 쓴다: 관찰값, 분류, 질문 답변, 조치, 다른 호스트, 재현 가능한 절차, 피드백.
3. 기록은 다른 사람이 내 작업을 되풀이할 수 있게 쓴다. 결과만 말고 쿼리를 적고, 시간은 UTC로.
4. 탐지는 킬 체인 중간에 떨어뜨려 놓는다. 뒤로는 전달까지, 앞으로는 C2와 목적까지 따라간다.
5. 닫은 사건마다 분류한다 — 판정, 유형, 핵심 시간, 탐지 출처, 장비 유형, 동기, 요약 — 그리고 시간의 정의는 한 번 정한다.
6. 우리가 분류한 사건이 가장 관련 깊은 위협 인텔리전스다.
7. 방어할 수 없는 귀속은 주장하지 않는다. 대신 내부 클러스터, 동기, TTP를 추적한다.

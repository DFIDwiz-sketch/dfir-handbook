# 구조화된 분석 기법 { #structured-analysis }

!!! abstract "한 줄 요약"
    지각과 기억 섹션은 분석가가 왜 틀리는지 보여 줬고, 보안 사고 모델 섹션은 연장통을 채웠습니다. 이 섹션이 해결책입니다. 불완전하고 애매한 데이터로도 분석을 믿을 만하게 만드는 방법들 — 시스템 1과 시스템 2 사고, "데이터가 더 필요한가?"라는 질문과 진단력 있는 증거, 구조화된 분석 기법의 네 갈래, 구조화된 브레인스토밍과 가설 세우기, 가설 평가에서 흔한 실수와 확증 편향, 경쟁 가설 분석(ACH), 링크 분석과 이벤트 매트릭스 — 을 실제 같은 경보와 로그로 보여 줍니다.

## 읽는 순서 { #reading-order }

| # | 페이지 | 핵심 |
| --- | --- | --- |
| 1 | [시스템 1과 시스템 2, "데이터가 더 필요한가?", 구조화된 분석 기법 — 빠른 생각에 브레이크 걸기](system1-2-sat.md) | 섹션 계획(생성, 평가, 정리), 시스템 1 대 시스템 2 비교와 직감을 끄는 게 아니라 고삐를 거는 이유, 시스템 2 방아쇠 목록, 필드 단위로 읽는 "불가능한 이동" 경보 — 로그인 로그, 기기 ID, 토큰 안의 MFA 기록, 세션 쿠키 재사용(T1557, T1539, T1550.004, T1114.003), 모자이크 방식 대 의학 진단, 진단력, 가설 셋과 증거 표와 가르는 검사로 보는 PowerShell 다운로드 경보, 한 줄씩 읽는 4688(부모 `explorer.exe`, 권한 상승 유형)과 4104 스크립트 블록(T1059.001, T1105, T1204.004, T1036.005, T1547.001), SAT란 무엇인가 — 분해와 외부화, 조종사의 체크리스트, 네 갈래와 SOC 사건에서 각각 쓰는 곳, 사건 하나로 네 갈래 따라가기, 2026년 관점(AI 분류와 자동화 편향, Kahneman과 재현성, ACH에 대한 엇갈린 연구), 확인 문제 |
| 2 | [가설 세우기, 평가의 실수, 확증 편향 — 제대로 브레인스토밍하고 내가 틀렸음을 증명하려 애쓰기](hypothesis-generation.md) | 2 – 4 – 8 수수께끼 규칙 몸풀기, 집단 사고·기준점 효과·섣부른 종결을 막는 구조화된 브레인스토밍, 네 원칙(판단 미루기, 양이 질을 낳는다, 스스로 만든 제약 없애기, 아이디어 섞기)과 조용히 쓰기부터 하는 SOC용 15분 순서, Zeek `conn.log`/`ssl.log`로 필드 하나씩 읽는 파일 서버 18 GB 업로드, 시간대 함정, 정상·악성·시험·"데이터가 틀림" 묶음의 가설 열네 개(T1567.002, T1048, T1041, T1074.002), 기준점 효과·확증 편향·섣부른 종결, 같은 사건으로 보는 적당히 만족하기·점진주의·합의·유추에 기댄 추론과 플레이북 대 유추, 퍼즐의 답과 Wason의 실험, 반증 검사 설계 — 백업 콘솔, 도메인 나이, 서비스 계정의 4624 로그온 유형 10(T1021.001, T1078.002), 이름 바꾼 rclone(T1036.003), 2026년 관점(브레인스토밍 짝이자 닻인 AI, 데이터만 훔치는 협박), 확인 문제 |
| 3 | [경쟁 가설 분석(ACH) — 모든 설명에 증거를 대 보고, 끝까지 죽지 않는 설명을 남기기](ach.md) | Popper의 반증과 ACH가 더하는 것(다른 설명 강제, 반박, 빠짐없는 검토, 감사 추적), 이유와 함께 보는 일곱 단계와 이정표, 새벽 2시 30분에 서버 37대를 건드린 관리자 계정 — 서로 배타적인 가설 다섯, 4624 유형 3과 10, `Temp` 배치 파일을 돌리는 무작위 이름 서비스 7045, 4697, 없는 4698, 변경 일정표와 스캐너 일정을 포함한 증거 여덟(T1078.002, T1021.001, T1021.002, T1569.002, T1543.003, T1053.005), 칸마다 채점한 매트릭스, "경우에 따라 다름" 칸, 진단력 없는 증거 빼기, 지지가 아니라 불일치 세기, 증거 하나로 기각한 가설의 민감도, 가능성 단어로 쓴 7단계 보고, 요령 — 증명 안 됨 대 반박됨, 보여야 할 것과 안 보여야 할 것, 제대로 도는 센서에서만 없음 쓰기, 열 문제, 공개된 WannaCry ACH와 이후 정부의 공식 지목, 세 줄짜리 미니 ACH와 검토 질문 셋, 2026년 관점(Dhami 외 2019의 엇갈린 결과, AI가 만든 매트릭스 초안, 정해진 가능성 단어), 확인 문제 |

!!! info "이어서 추가될 내용"
    링크 분석과 Maltego 같은 도구, 이벤트 매트릭스 차트, 미리 만든 사고 추적 양식, 구조화된 분석 정리 — 이것으로 섹션을 마칩니다.

## 꼭 기억할 것 { #must-know }

1. 편향의 해결책은 노력이 아니라 방법이다.
2. 시스템 1은 빠르고 일상 사건에서 대개 맞다. 끄지 말고 고삐를 건다.
3. 분명한 방아쇠에서 시스템 2로 바꾼다. 걸린 게 클 때, 처음 볼 때, 모순될 때, 되돌릴 수 없는 결정일 때, 큰 사건에 금방 확신이 들 때.
4. 데이터가 늘면 정확도보다 자신감이 먼저 오른다. 진단하라. 가설을 적고, 그것들을 갈라 주는 검사를 돌린다.
5. 모든 가설과 맞는 증거는, 아무리 무서워 보여도 진단 가치가 거의 없다.
6. 구조화된 기법은 쪼개고 머리 밖으로 꺼낸다. 직감을 견제하는 장치이지, 결론의 증명이 아니다.
7. 판단하기 전에 만든다. 조용히 쓰기부터, 비판 금지, 뻔한 것 넘어서기, "데이터가 틀림"도 넣기.
8. 적당히 만족하기, 점진주의, 합의, 유추에 기댄 추론을 조심한다.
9. 확인해 주는 증거는 증명하는 게 적다. 가설마다 "이게 거짓이라면 무엇이 보일까?"를 묻고 찾아본다.

# 구조화된 분석 기법 { #structured-analysis }

!!! abstract "한 줄 요약"
    지각과 기억 섹션은 분석가가 왜 틀리는지 보여 줬고, 보안 사고 모델 섹션은 연장통을 채웠습니다. 이 섹션이 해결책입니다. 불완전하고 애매한 데이터로도 분석을 믿을 만하게 만드는 방법들 — 시스템 1과 시스템 2 사고, "데이터가 더 필요한가?"라는 질문과 진단력 있는 증거, 구조화된 분석 기법의 네 갈래, 구조화된 브레인스토밍과 가설 세우기, 가설 평가에서 흔한 실수와 확증 편향, 경쟁 가설 분석(ACH), 링크 분석과 이벤트 매트릭스 — 을 실제 같은 경보와 로그로 보여 줍니다.

## 읽는 순서 { #reading-order }

| # | 페이지 | 핵심 |
| --- | --- | --- |
| 1 | [시스템 1과 시스템 2, "데이터가 더 필요한가?", 구조화된 분석 기법 — 빠른 생각에 브레이크 걸기](system1-2-sat.md) | 섹션 계획(생성, 평가, 정리), 시스템 1 대 시스템 2 비교와 직감을 끄는 게 아니라 고삐를 거는 이유, 시스템 2 방아쇠 목록, 필드 단위로 읽는 "불가능한 이동" 경보 — 로그인 로그, 기기 ID, 토큰 안의 MFA 기록, 세션 쿠키 재사용(T1557, T1539, T1550.004, T1114.003), 모자이크 방식 대 의학 진단, 진단력, 가설 셋과 증거 표와 가르는 검사로 보는 PowerShell 다운로드 경보, 한 줄씩 읽는 4688(부모 `explorer.exe`, 권한 상승 유형)과 4104 스크립트 블록(T1059.001, T1105, T1204.004, T1036.005, T1547.001), SAT란 무엇인가 — 분해와 외부화, 조종사의 체크리스트, 네 갈래와 SOC 사건에서 각각 쓰는 곳, 사건 하나로 네 갈래 따라가기, 2026년 관점(AI 분류와 자동화 편향, Kahneman과 재현성, ACH에 대한 엇갈린 연구), 확인 문제 |

!!! info "이어서 추가될 내용"
    가설 세우기와 확증 편향, 이어서 경쟁 가설 분석(ACH), 그리고 링크 분석과 이벤트 매트릭스.

## 꼭 기억할 것 { #must-know }

1. 편향의 해결책은 노력이 아니라 방법이다.
2. 시스템 1은 빠르고 일상 사건에서 대개 맞다. 끄지 말고 고삐를 건다.
3. 분명한 방아쇠에서 시스템 2로 바꾼다. 걸린 게 클 때, 처음 볼 때, 모순될 때, 되돌릴 수 없는 결정일 때, 큰 사건에 금방 확신이 들 때.
4. 데이터가 늘면 정확도보다 자신감이 먼저 오른다. 진단하라. 가설을 적고, 그것들을 갈라 주는 검사를 돌린다.
5. 모든 가설과 맞는 증거는, 아무리 무서워 보여도 진단 가치가 거의 없다.
6. 구조화된 기법은 쪼개고 머리 밖으로 꺼낸다. 직감을 견제하는 장치이지, 결론의 증명이 아니다.

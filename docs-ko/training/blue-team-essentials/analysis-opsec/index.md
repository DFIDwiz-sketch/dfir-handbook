# 분석 OPSEC { #analysis-opsec }

!!! abstract "한 줄 요약"
    조사 섹션이 경보를 조사하는 법을 보여 줬다면, 이 섹션은 **공격자에게 눈치채이지 않고** 조사하는 법을 다룹니다. 분석가에게 작전 보안이 무슨 뜻이고 왜 기회주의 공격보다 표적 공격에서 훨씬 중요한지, 인텔리전스를 나누고 그걸로 행동하는 규칙(신호등 프로토콜과 허용 행동 프로토콜), 그리고 실무 습관 — 수동 출처부터, OSINT 도구마다 무엇을 공유하는지 알기, 검색 대 스캔, 흔한 OPSEC 실패(공개 IOC 제출, 공격자 인프라와 상호작용, 섣부른 차단), 추적되지 않는 연결, 분석용 PC, Tor — 를 봅니다.

## 꼭 기억할 것 { #must-know }

1. 바깥을 향한 단계마다 묻는다. "이게 표적일 수 있나, 이 행동이 공격자에게 무엇을 알려 줄까?"
2. 표적 공격에서 공격자가 우리가 안다는 걸 모르는 건 지킬 가치가 있는 이점이다.
3. 공격자는 자기 DNS·웹 로그를 보고, 우리가 쓰는 공개 스캔 사이트를 똑같이 검색한다.
4. 우리 로그는 아무에게도 신호를 주지 않는다. 먼저 거기를 검색한다.
5. TLP는 누구에게 말해도 되는지, PAP는 무엇을 해도 되는지 정한다. 둘 다 읽고, 둘 다 붙인다.
6. TLP:GREEN은 절대 공개가 아니고, 출처가 붙인 추가 제한은 언제나 적용된다.
7. 스캔 전에 검색, 업로드 전에 해시 — 그리고 도구가 실제로 무엇을 하는지 시험한다.
8. 상호작용은 추적되지 않는 분석 PC에서만. Tor는 IP를 숨기지, 고유 URL을 숨기지 않는다.
9. 능숙한 공격자의 C2 채널 하나를 나머지를 알기 전에 끊지 않는다 — 피해가 진행 중이 아니라면.

# 조사 질문과 분석 { #investigation }

!!! abstract "한 줄 요약"
    구조화된 분석 섹션이 생각하는 방법을 줬다면, 이 섹션은 그걸 실제 증거에 씁니다. 먼저 조사를 어떻게 시작하는지 — 네 가지 질문(무엇에 답하나, 어떤 데이터가 답해 주나, 어떻게 얻나, 그게 무엇을 말해 주나), 답을 쥐고 있는 수많은 네트워크·호스트·대안 출처, 바깥 정보가 필요한 때, 맞는 도구로 데이터를 꺼내는 법 — 를 보고, 이어서 해석으로 넘어갑니다. 네트워크 이벤트를 계층별로(IP와 도메인, 포트, TLS 인증서, 애플리케이션 메타데이터와 내용), 이메일 링크와 피싱 페이지, 표적 공격 대 기회주의 공격, 비즈니스 이메일 침해(BEC).

    표적형 대 기회주의형 공격, 단축 링크 클릭 추적, 비밀번호 입력란이 실제로 어디로 가나, 비즈니스 이메일 침해 탐지, 조사 질문 정리 — 이걸로 이 섹션이 끝납니다.

## 꼭 기억할 것 { #must-know }

1. 검색하기 전에 계획한다. 질문과 필요한 데이터를 먼저 티켓에 적는다.
2. 첫 질문은 언제나 "이 경보가 진짜인가 — 그리고 이것과 똑같아 보이는 다른 건 뭔가?"이다.
3. 가장 손닿기 쉬운 출처가 아니라 가장 확실하게 답하는 출처를 고른다.
4. 연결 하나는 여러 곳에 기록된다. 1차 출처가 없으면 나머지를 쓰되, 보관 기간을 알아 둔다.
5. 호스트에서는 무엇이 실행됐나, 왜 실행됐나, 언제 처음 실행됐나를 묻는다.
6. 바깥 서비스에 하는 조회나 업로드는 모두 공개이기도 하다.
7. 모든 계층을 확인한다. 목적지, 포트, TLS 포장, 내용 — 공격자는 하나만 속이면 된다.
8. 드문 목적지는 볼 만하다. 믿을 만한 서비스도 나쁜 내용을 실어 나를 수 있고, 증명은 바이트만 한다.

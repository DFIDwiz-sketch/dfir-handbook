# 경보 분류와 우선순위 { #alert-triage }

!!! abstract "한 줄 요약"
    분석 파트가 여기서 시작합니다. 분석가보다 경보가 많을 때 다음에 무엇을 열까? 이 섹션은 앞에서 배운 네트워크·호스트 지식을 순위 매기는 습관으로 바꿉니다. 실무에서 "위험하다"가 무슨 뜻인지, 거의 끝나 가는 공격과 이제 막 시작한 공격을 어떻게 가르는지, 경보 데이터에서 유출, 파괴, 민감한 대상, 표적 공격자를 어떻게 알아보는지, 실제 대기열에 어떻게 우선순위를 매기는지.

!!! info "이어서 추가될 내용"
    데이터 유출과 파괴 시도 알아보기, 민감한 호스트·사용자·데이터 알아보기, 표적 공격의 신호. 이어서 IDS·익스플로잇 경보, 처음 보는 경보, 우선순위 낮은 경보의 순위 매기기와 분류 정리.

## 꼭 기억할 것 { #must-know }

1. 도착 순서가 아니라 결과의 무게로 분류한다. 새 경보가 오면 순위를 다시 매긴다.
2. 위험하다 = 성공하면 피해를 주거나, 돈이 많이 들거나, 되돌리기 어렵다.
3. 순서: 거의 끝남 → 가치 높은 대상 → 고급·표적 → 처음 보거나 가장 적게 울림.
4. 공격자의 예상 목표를 미리 적어 둔다. "거의 끝"은 *그 목표*에 가깝다는 뜻이다.
5. 엉뚱한 곳의 특권 계정(낯선 호스트의 4624 + 4672)은 마지막 단계의 신호다.
6. 모든 경보를 공격 모델 위에 올리고 몇 걸음 남았는지 묻는다. 침해는 빙빙 돈다는 걸 잊지 않는다.
7. 순위를 매기기 전에 호스트, 사용자, IP로 경보를 묶는다. 중간 경보 셋이 치명적인 사건 하나일 수 있다.
8. 심각도는 규칙의 의견이고, 위험은 이 자산, 이 맥락에서 일어난 이 사건이다.

# 고통의 피라미드, MITRE ATT&CK, 언제 어떤 모델을 쓰나 — 공격자를 괴롭히고 맞는 렌즈 고르기 { #pyramid-attack-summary }

!!! abstract "이 페이지에서 다루는 것"
    이 섹션의 마지막 두 모델과, 모든 모델이 어떻게 맞물리는지입니다. 먼저 David Bianco의 <strong>고통의 피라미드(Pyramid of Pain)</strong> — 맨 아래 해시 값부터 맨 위 전술·기법·절차(TTP)까지 여섯 종류의 지표를, 막았을 때 공격자가 얼마나 아파하는지로 줄 세운 것 — 를 가상 캠페인 하나의 실제 같은 지표로 단계마다 보여 줍니다. 한 바이트만 바꿔도 완전히 새로 나오는 SHA-256, IP와 도메인, 네트워크 흔적이 담긴 Zeek `http.log` 한 줄, 도구를 잡는 YARA 규칙과 행동을 잡는 Sigma 규칙을 한 줄씩 읽고, 막을 때마다 공격자가 무엇을 했는지까지. 이어서 <strong>공격 지표(IOA) 대 침해 지표(IOC)</strong>와 탐지 성숙도 수준(Detection Maturity Level). 다음은 **MITRE ATT&CK**: 전술, 기법, 하위 기법, 절차, 매트릭스들, 기법 페이지가 주는 것, 가상 침입을 기법 하나하나 매핑하기, 한 줄씩 읽는 Navigator 레이어, 방어 범위 공백으로 하는 헌팅. 마지막으로 **언제 어떤 모델을 쓰나** — 분류, 사고 대응, 방어 전략, 헌팅, 위협 인텔리전스, 속도 — 와 모든 모델은 틀렸지만 일부는 쓸모 있다는 당부. 2026년 관점과 확인 문제로 이 페이지와 섹션을 마칩니다.

!!! note "표기"
    **[보충]** = 꼭 알아야 할 실무 보충, **[정정]** = 흔히 잘못 알려진 내용 정정, **[변경됨]**/**[주의]** = 최근 바뀐 점과 옛 방식대로 하면 위험한 점. 회사(Kestrel Logistics), 캠페인 이름, 호스트 이름, 계정, 도메인, IP, 파일 이름, 규칙, 로그 줄은 모두 설명용 가상 값(`.example`, 문서용·사설 IP)입니다. 프레임워크와 그 저자에 대한 설명은 제 말로 풀어 썼습니다.

## 한눈에 보는 핵심 8가지 { #key-points }

1. **고통의 피라미드는 지표를, 그걸 막았을 때 공격자가 겪는 고통으로 줄 세운다.** 아래에서 위로: 해시 값(바꾸기 아주 쉬움), IP 주소(쉬움), 도메인 이름(간단함), 네트워크·호스트 흔적(귀찮음), 도구(어려움), TTP(힘듦).
2. **해시는 장기적으로 가장 약한 방어다.** 한 비트만 바꿔도 새 해시가 된다. 싸니까 막기는 하되, 해시 차단을 사고의 끝으로 여기지 않는다.
3. **IP와 도메인은 공격자에게 몇 분과 몇 달러짜리다.** 새 클라우드 서버와 새 도메인은 싸다. 이 수준의 차단은 몇 시간에서 며칠을 벌어 준다.
4. **흔적, 도구, TTP는 공격자를 처음부터 다시 시작하게 만든다.** URI 패턴 규칙은 코드를 고치게 하고, 도구 규칙은 도구를 다시 만들게 하고, 행동 탐지는 일하는 방식을 새로 짜게 한다. 탐지에 들인 노력이 가장 오래 값을 하는 곳이 여기다.
5. **공격 지표(IOA)는 공격자가 *하고 있는 일*을, 침해 지표(IOC)는 공격자가 *남기고 간 것*을 말한다.** IOC는 사후 대응이고 갈아 치우기 쉽다. IOA는 다음 침입도 잡는다.
6. **MITRE ATT&CK은 피라미드 꼭대기의 목록이다.** 전술은 공격자의 목표(*왜*), 기법과 하위 기법은 거기 가는 방법(*어떻게*), 절차는 실제 세상의 구체적 사례. 기법 페이지마다 누가 썼는지, 어떻게 완화하고 탐지하는지 적혀 있다. 블루팀 체크리스트다.
7. **일마다 맞는 모델이 있다.** 분류: 킬 체인이나 공격 생명 주기. 사고 대응: 사고 대응 주기, 그다음 무엇을 막을지는 고통의 피라미드. 방어 전략: 위협 모델과 공격 트리. 헌팅과 분석 규칙 개발: ATT&CK. 위협 인텔리전스: 세 수준, F3EAD, 다이아몬드 모델. 속도: OODA.
8. **모든 모델은 틀렸다. 일부가 쓸모 있을 뿐.** 모델은 단순하게 만들고, 단순하게 만들면 세부가 빠진다. 모든 사건을 억지로 맞출 규칙이 아니라 출발점이 되는 뼈대로 쓴다. 빈틈은 분석가의 판단이 채운다.

## SOC에서 왜 중요한가 { #why }

가게에 자꾸 오는 좀도둑을 떠올려 보세요. 입구에서 *그 사람의 빨간 재킷*을 막으면 재킷을 바꿔 입을 때까지 — 내일까지 — 통합니다. 차 번호판을 막으면 버스를 탈 때까지 통합니다. 그런데 그가 늘 짝과 함께 와서, 짝이 계산대 직원의 주의를 끄는 동안 뒤쪽 통로에서 가방을 채운다는 걸 알아내고 직원들이 그 패턴을 알아보도록 교육하면, 그 사람에게도, 같은 수법을 쓰는 다른 모든 좀도둑에게도 통합니다. 무엇을 입고 오든. 재킷은 해시이고, 번호판은 IP이고, 주의 끌기 수법이 TTP입니다.

기술적인 현실로 돌아오면, 사고 중에는 *뭐라도* 빨리 막으라는 압박이 있고, 가장 막기 쉬운 건 피라미드 바닥 — 샌드박스가 준 해시, 프록시 로그의 C2 IP — 입니다. 그런 차단은 꼭 필요하지만 그걸로 끝나는 건 없습니다. 고통의 피라미드는 오래가는 가치가 어디 있는지 알려 주고, ATT&CK은 피라미드 꼭대기에 공통의 이름을 붙여서 탐지 엔지니어, 위협 인텔 보고서, 사고 타임라인이 모두 같은 말을 하게 해 줍니다. 그리고 *어떤* 질문에 *어떤* 모델을 꺼낼지 아는 것이, 새벽 3시에 경보 대기열 앞에서 이 섹션의 연장통 전체를 쓸모 있게 만드는 힘입니다.

## 고통의 피라미드 { #pyramid }

### 모델 { #pyramid-model }

David Bianco는 큰 사고 대응 회사의 헌팅 팀장이던 2013년, 공격자의 작전에 대해 뭔가 알게 됐을 때 그들의 하루를 가장 효과적으로 망치는 방법을 생각하는 틀로 고통의 피라미드를 발표했습니다. 우리가 탐지하거나 막기 시작했을 때 공격자가 그걸 바꾸는 데 드는 비용으로 지표 여섯 종류를 줄 세웁니다.

```
                 /\
                /  \        TTPs                    Tough!
               /----\
              /      \      Tools                   Challenging
             /--------\
            /          \    Network/Host Artefacts  Annoying
           /------------\
          /              \  Domain Names            Simple
         /----------------\
        /                  \ IP Addresses           Easy
       /--------------------\
      /                      \ Hash Values          Trivial
     /________________________\
```

그림 오른쪽 말은 공격자 입장의 난이도입니다. 위에서부터 힘듦(Tough), 어려움(Challenging), 귀찮음(Annoying), 간단함(Simple), 쉬움(Easy), 아주 쉬움(Trivial). 높은 단계에서 탐지하고 막을수록 공격자는 계속하기 위해 더 많은 일을 해야 하고, 우리 탐지는 더 오래 쓸모 있습니다.

### 예제: 모든 단계에서 본 KL-CAMP-01 { #pyramid-example }

Kestrel Logistics에는 캠페인 KL-CAMP-01(이 섹션 내내 쓰는 것)의 사건이 세 개 있습니다. SOC가 아는 것을 단계별로, 그 단계의 탐지가 어떻게 생겼는지, 각 차단 뒤에 공격자가 무엇을 했는지 봅니다.

**1단계 — 해시 값(아주 쉬움).** 샌드박스가 백도어 `updsvc.exe`의 SHA-256을 줍니다. 왜 이게 바닥일까요? 암호학적 해시는 파일의 *어느* 비트든 바뀌면 완전히 달라집니다. 글자 하나만 다른 텍스트 파일 두 개로 보는 무해한 시연:

```
$ printf 'build-id: 0001\n' > sample_v1.txt
$ printf 'build-id: 0002\n' > sample_v2.txt
$ sha256sum sample_v1.txt sample_v2.txt
fb23786473ab56b0e2a87ab67e0e77a156eeef58cce9a1eacc18c4e610225cb5  sample_v1.txt
466a2789bfd273ff55423c3748c40da98273e2837e60f0236a7accf1ac61ccd9  sample_v2.txt
$ cmp -l sample_v1.txt sample_v2.txt
14  61  62
```

- `printf … > sample_v1.txt` — 한 줄짜리 파일을 씁니다. 두 번째 파일은 마지막 숫자만 다릅니다.
- `sha256sum` — 파일마다 SHA-256 해시를 출력합니다. 파일은 한 바이트만 다른데, 두 해시에는 알아볼 만한 공통점이 전혀 없습니다.
- `cmp -l` — 다른 바이트를 모두 보여 줍니다. `14`번째 바이트, 8진수 `61`(문자 `1`) 대 8진수 `62`(`2`). 한 바이트를 넣으면 완전히 새 해시가 나옵니다.

악성코드 제작자는 이걸 자동으로 합니다. 피해자마다 몇 바이트를 바꾸거나 다시 패킹하는 빌더를 쓰면 표적마다 고유한 해시가 생깁니다. 사건 B에서 Kestrel은 해시를 막았고, 사건 C는 같은 코드로 만든 해시가 다른 실행 파일을 썼습니다.

**2단계 — IP 주소(쉬움).** C2가 198.51.100.23. 새 클라우드 서버는 몇 분이면 빌리고, 많은 공격자가 어차피 클라우드 업체, VPN, 해킹한 호스트를 거쳐 옵니다. 사건 A에서 IP를 막자 백도어는 하루 안에 새 IP로 옮겨 갔습니다.

**3단계 — 도메인 이름(간단함).** `telemetry-cdn.example`, `freightdocs-portal.example`. 도메인 등록은 몇 달러와 몇 분이면 됩니다. 어떤 공격자는 동적 DNS나 호스팅 서비스의 무료 하위 도메인, 혹은 정상 클라우드 서비스를 씁니다. IP보다는 조금 귀찮지만(등록, DNS 설정, 인증서) 여전히 쌉니다.

**4단계 — 네트워크·호스트 흔적(귀찮음).** *어디에 연결하는지*가 아니라 *도구가 어떻게 행동하는지*의 흔적입니다. 사건 A의 Zeek `http.log` 한 줄(공격자가 모두 HTTPS로 바꾸기 전):

```
ts=2026-09-22T10:05:12Z  uid=C8fQ2b  id.orig_h=10.20.6.31  id.resp_h=203.0.113.77  id.resp_p=80
method=POST  host=update-cdn.example  uri=/api/v2/ping  user_agent=Mozilla/5.0 (Windows NT 10.0; Win64; x64) UpdSvc/2.1
request_body_len=64  response_body_len=0  status_code=204
```

- `method=POST`, `uri=/api/v2/ping` — 백도어가 어느 C2 서버에서든 쓰는 체크인 경로. **네트워크 흔적**입니다.
- `user_agent=… UpdSvc/2.1` — 브라우저처럼 보이는 User-Agent 끝에 도구 이름을 붙였습니다. 전형적인 허술한 흔적입니다.
- `request_body_len=64`, `response_body_len=0`, `status_code=204` — 고정된 64바이트 체크인에, 할 일이 없으면 "204 No Content"로 답합니다. 300초마다 똑같이. 일정한 크기와 주기도 흔적입니다.

호스트 쪽 흔적은 설치 경로 `%APPDATA%\UpdSvc\updsvc.exe`, Run 키 값 이름 `UpdSvc`, 그리고 `Global\UpdSvcMtx`라는 뮤텍스(mutex, 악성코드가 하나만 실행되도록 만드는 이름 붙은 잠금)입니다. `/api/v2/ping`과 고정된 64바이트 POST 패턴에 대한 탐지가 사건 C의 비컨을 완전히 새 도메인과 IP에서 잡았습니다. 공격자가 빠져나가려면 코드를 고쳐야 했습니다.

**5단계 — 도구(어려움).** 빌드 하나가 아니라 백도어 *계열*에 대한 탐지입니다. 가상의 `updsvc` 계열을 잡는 YARA 규칙(YARA는 문자열과 바이트 패턴으로 파일을 기술하는 도구):

```
rule KL_CAMP01_UpdSvc_Backdoor
{
    meta:
        description = "Invented example: UpdSvc backdoor family used by KL-CAMP-01"
        tlp = "AMBER"
    strings:
        $uri   = "/api/v2/ping" ascii wide
        $mutex = "Global\\UpdSvcMtx" ascii wide
        $ua    = "UpdSvc/" ascii
        $cfg   = { 2C 01 00 00 40 00 00 00 }
    condition:
        uint16(0) == 0x5A4D and filesize < 2MB and 3 of them
}
```

- `rule KL_CAMP01_UpdSvc_Backdoor` — 규칙 이름. 좋은 이름은 캠페인과 계열을 말해 줍니다.
- `meta:` — 설명과 공유 등급. 매칭에는 안 쓰입니다.
- `$uri`, `$mutex`, `$ua` — 도구 안의 문자열. `ascii wide`는 일반 인코딩과 UTF-16 둘 다 맞춥니다(Windows 프로그램은 문자열을 UTF-16으로 담는 일이 많음).
- `$cfg = { 2C 01 00 00 40 00 00 00 }` — 바이트 패턴. 설정 안에 나란히 저장된 리틀 엔디언 숫자 300(`0x12C`, 비컨 주기)과 64(`0x40`, 체크인 크기).
- `uint16(0) == 0x5A4D` — 파일이 `MZ`로 시작한다. 즉 Windows 실행 파일.
- `filesize < 2MB and 3 of them` — 작은 파일이고, 패턴 넷 중 최소 셋이 맞는다. 셋을 요구하니, 다시 빌드하면서 문자열 하나를 바꿔도 여전히 맞습니다.

`updsvc`를 다시 빌드해서 해시가 바뀌어도 모두 걸립니다. 빠져나가려면 공격자는 도구를 다시 쓰거나 갈아 치워야 합니다. 진짜 개발 작업입니다.

**6단계 — TTP(힘듦).** 도구, 도메인, 해시와 상관없이 *행동*을 잡는 탐지입니다. KL-CAMP-01이 늘 하는 행동은 "사용자가 압축 파일 안의 LNK를 열고, Explorer가 숨긴 인코딩 스크립트 호스트를 실행한다"입니다. Sigma 규칙(Sigma는 업체 중립적인 로그 탐지 형식이고, SIEM마다 그 질의 언어로 변환해 씀):

```
title: Hidden encoded PowerShell launched by Explorer (possible malicious LNK)
status: experimental
logsource:
    product: windows
    category: process_creation
detection:
    selection_parent:
        ParentImage|endswith: '\explorer.exe'
    selection_child:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_flags:
        CommandLine|contains|all:
            - ' -w hidden'
            - ' -enc'
    condition: selection_parent and selection_child and selection_flags
tags:
    - attack.t1204.002
    - attack.t1059.001
    - attack.t1027
level: high
```

- `title` — 규칙 이름: "Explorer가 실행한 숨긴 인코딩 PowerShell(악성 LNK 가능성)".
- `logsource: product: windows, category: process_creation` — 프로세스 시작 이벤트에 대해 돌립니다. Windows **4688**이나 Sysmon 이벤트 1. **이벤트 4688**("새 프로세스가 생성됐다")은 프로세스가 시작될 때마다 생기고, 명령줄 감사를 켜 두면 명령 전체를 기록합니다. 공격자에게 중요한 이유는, 페이로드가 디스크에 한 번도 닿지 않아도 실행 자체는 기록되기 때문입니다.
- `selection_parent` — 부모 프로세스가 Explorer. 사용자가 무언가를 더블클릭하면 이렇게 됩니다.
- `selection_child` — 자식이 PowerShell(Windows PowerShell 또는 PowerShell 7).
- `selection_flags`의 `contains|all` — 명령줄에 숨긴 창 옵션과 인코딩된 명령이 *둘 다* 있다. (실제 규칙은 이 옵션들의 줄임말과 다른 철자도 다룹니다. 여기선 짧게 줄였습니다.)
- `condition` — 셋 다 맞아야 한다.
- `tags` — ATT&CK 기법: **T1204.002 User Execution: Malicious File**, **T1059.001 Command and Scripting Interpreter: PowerShell**, **T1027 Obfuscated Files or Information**.

이 규칙은 도메인도, 해시도, 심지어 백도어도 신경 쓰지 않습니다. KL-CAMP-01의 *다음* 도구도, 같은 수법을 쓰는 다른 행위자도 잡습니다. 빠져나가려면 공격자는 코드를 실행시키는 방식 자체를 바꿔야 합니다. 새 최초 침투 방법, 새 수법, 다시 익히기. 그게 "힘듦" 단계입니다.

### 막을 때마다 공격자가 한 일 { #pyramid-after-block }

| Kestrel이 막은 것 | 단계 | 공격자의 반응 | 공격자가 돌아오기까지 |
| --- | --- | --- | --- |
| `updsvc.exe` 해시(사건 B) | 해시 | 실행 파일 다시 빌드 | 다음 캠페인 물결(~3주, 차단과는 무관) |
| C2 IP(사건 A) | IP | 새 클라우드 서버 | 1일 미만 |
| C2 도메인(사건 A) | 도메인 | 새 IP에 새 도메인 | ~1일 |
| `/api/v2/ping` + 64바이트 POST 패턴 | 흔적 | (아직 안 바뀜 — 계속 비컨을 잡는 중) | — |
| 계열 YARA 규칙 | 도구 | (아직 안 바뀜) | — |
| Explorer → 숨긴 인코딩 PowerShell | TTP | 새 최초 침투 수법이 필요 | — |

**[보충]** 실무에서는 *둘 다* 합니다. 싼 지표는 빠르고 지금 침입을 멈추니 바로 막고, *동시에* 탐지 엔지니어링 시간은 오래가는 위쪽에 씁니다. 피라미드는 "해시를 막지 마라"가 아니라 "거기서 멈추지 마라"라고 말합니다. 위쪽 탐지는 잡음도 많은 편이라(정상 관리자도 숨긴 PowerShell을 돌림) 다듬어야 합니다. 오래가는 대가입니다.

### 공격 지표 대 침해 지표 { #ioa-vs-ioc }

같은 이야기를 좀 더 둘로 딱 나눠 말하면 <strong>침해 지표(Indicator of Compromise, IOC)</strong> 대 <strong>공격 지표(Indicator of Attack, IOA)</strong>입니다. 한 EDR 업체가 널리 알린 구분입니다. 은행 강도로 생각해 보세요. "강도는 빨간 모자를 썼다"는 IOC입니다. 사실이지만 적는 순간 이미 지난 정보이고, 다음에 파란 모자를 쓰면 쓸모없습니다. 누군가 은행을 *사전 답사하고*, 직원 통로로 슬쩍 들어가고, 금고 문을 건드리는 걸 잡는 건 IOA입니다. *진행 중인* 공격의 관찰이고, 같은 방식으로 하는 어떤 강도에게나 통합니다.

| | IOC | IOA |
| --- | --- | --- |
| 말하는 것 | 남기고 간 증거 | 지금 벌어지는 활동 |
| 피라미드 단계 | 주로 아래(해시, IP, 도메인) | 주로 위(행동의 흔적, TTP) |
| 방어 자세 | 사후 대응: "전에 본 적 있나?" | 사전 대응: "지금 누가 이걸 하고 있나?" |
| KL-CAMP-01 예 | `telemetry-cdn.example`, `updsvc.exe`의 해시 | Explorer가 숨긴 인코딩 PowerShell을 띄움, 새로 등록된 도메인으로 가는 고정 주기 POST 비컨 |

**[보충]** Ryan Stillions의 <strong>탐지 성숙도 수준(Detection Maturity Level, DML)</strong> 모델(2014)은 같은 사다리를 조직의 탐지가 얼마나 성숙했는지 말하는 데 씁니다. DML-0(탐지 없음)에서 시작해 원자 지표(1), 호스트·네트워크 흔적(2), 도구(3), 절차(4), 기법(5), 전술(6), 그리고 공격자의 전략(7)과 목표(8)까지. IOC 피드만 받아 쓰는 SOC는 피드를 몇 개 사든 DML-1에 있습니다.

## MITRE ATT&CK { #attack }

### 무엇인가 { #attack-what }

**MITRE ATT&CK**(Adversarial Tactics, Techniques, and Common Knowledge)은 실제 공격자가 어떻게 움직이는지 정리한 공개 지식 베이스입니다. 연방 정부 지원 연구 센터들을 운영하는 미국 비영리 단체 MITRE가 관리합니다. 사실상 고통의 피라미드 꼭대기의 목록이고, 탐지 엔지니어링, 위협 인텔리전스, 레드팀의 공통 언어가 됐습니다. 방어자라면 누구나 잘 알아야 합니다.

구조는 이렇습니다.

- <strong>전술(Tactic)</strong> — 맨 위에 가로로 놓인 열들. 그 시점의 공격자 목표, 즉 *왜*. 예: Initial Access(최초 침투), Execution(실행), Persistence(지속성), Privilege Escalation(권한 상승), Credential Access(자격 증명 접근), Discovery(탐색), Lateral Movement(횡적 이동), Collection(수집), Command and Control(명령 및 제어), Exfiltration(유출), Impact(영향). ID는 `TA0006`(Credential Access) 같은 모양입니다.
- <strong>기법(Technique)</strong> — 각 열 안의 항목. 그 목표에 닿는 방법, 즉 *어떻게*. ID는 `T1003`(OS Credential Dumping) 같은 모양.
- <strong>하위 기법(Sub-technique)</strong> — 기법 아래에 들어간 더 구체적인 변형. `T1003.001`(LSASS Memory), `T1003.003`(NTDS).
- <strong>절차(Procedure)</strong> — 실제로 관찰된 구체적 구현. "그룹 X가 도구 Y로 Z를 해서 LSASS를 덤프했다." 기법 페이지마다 예로 실려 있습니다.

**[정정]** 옛 자료는 Credential Access의 예로 "계정 조작, 무차별 대입, 자격 증명 덤프, 파일 속 자격 증명"을 드는 일이 많습니다. 지금 매트릭스에서 <strong>Brute Force(T1110)</strong>와 <strong>OS Credential Dumping(T1003)</strong>은 Credential Access 아래에 있고, 파일 속 자격 증명은 이제 하위 기법 <strong>Unsecured Credentials: Credentials In Files(T1552.001)</strong>이며, <strong>Account Manipulation(T1098)</strong>은 Persistence와 Privilege Escalation 아래에 있습니다. 기법 이름과 자리는 버전마다 옮겨 다닙니다. 늘 실제 사이트에서 확인하세요.

지식 베이스는 영역으로 나뉩니다. **Enterprise**(Windows, Linux, macOS, 그리고 클라우드 플랫폼 — IaaS, SaaS, 오피스 제품군, 아이덴티티 공급자 — 네트워크 장비, 컨테이너, ESXi), **Mobile**, **ICS**(산업 제어 시스템). 기법 말고도 **그룹**(사용한 기법이 붙은 활동 덩어리), **소프트웨어**(악성코드와 도구), **캠페인**, **완화책**, 그리고 버전 18부터는 기법마다 <strong>탐지 전략(detection strategy)</strong>과 분석 규칙 페이지가 있습니다. MITRE는 2018년에 처음 열린 사용자 콘퍼런스 ATT&CKcon도 운영합니다.

### 예제: 사건 C 매핑하기 { #attack-mapping }

사건을 매핑한다는 건, 공격자가 한 일 하나하나에 해당 기법과 그 증거를 적는 것입니다.

| 시각(UTC) | 일어난 일 | 증거 | 전술 | 기법 |
| --- | --- | --- | --- | --- |
| 08:41 | LNK가 든 ZIP을 구매팀에 이메일로 보냄 | 게이트웨이 로그, 이메일 헤더 | Initial Access | T1566.001 Phishing: Spearphishing Attachment |
| 08:47 | 사용자가 LNK를 엶 | 4688: explorer.exe → powershell.exe | Execution | T1204.002 User Execution: Malicious File |
| 08:47 | 숨긴, Base64 인코딩 PowerShell | 4688 명령줄 `-w hidden -enc` | Execution | T1059.001 PowerShell, T1027 Obfuscated Files or Information |
| 08:47 | HTTPS로 2단계 다운로드 | 프록시 로그, Zeek `ssl.log` | Command and Control | T1105 Ingress Tool Transfer |
| 08:48 | Run 키 `UpdSvc` → `%APPDATA%\UpdSvc\updsvc.exe` | Sysmon 13(레지스트리 값 설정) | Persistence | T1547.001 Registry Run Keys / Startup Folder |
| 08:48 → | 300초마다 `/api/v2/ping`으로 비컨 | Zeek `ssl.log`, EDR 네트워크 이벤트 | Command and Control | T1071.001 Application Layer Protocol: Web Protocols |

좋은 매핑의 규칙 셋:

- **추측이 아니라 증거를 매핑한다.** "다음엔 아마 Mimikatz를 썼을 것"은 줄이 될 수 없습니다. 못 봤으면 매핑하지 않습니다.
- **증거가 받쳐 주는 가장 구체적인 수준을 쓴다.** 증거가 보여 주면 하위 기법, 아니면 기법.
- **사용한 ATT&CK 버전을 적는다.** 기법과 전술이 옮겨 다니기 때문입니다(아래 2026년 관점).

### 예제: 방어 범위 레이어와 헌팅 { #attack-coverage }

**ATT&CK Navigator**는 매트릭스에 색을 칠하는 MITRE의 무료 웹 도구입니다. 예를 들어 우리가 탐지하는 기법을 칠합니다. 레이어는 JSON으로 저장됩니다. 줄인 레이어를 한 줄씩 읽어 봅니다.

```json
{
  "name": "Kestrel SOC detection coverage 2026-11",
  "domain": "enterprise-attack",
  "versions": { "attack": "20", "navigator": "5.1", "layer": "4.5" },
  "techniques": [
    { "techniqueID": "T1059.001", "score": 3, "comment": "Sigma: hidden encoded PowerShell; AMSI logs" },
    { "techniqueID": "T1547.001", "score": 2, "comment": "Sysmon 13 on workstations only" },
    { "techniqueID": "T1003.001", "score": 3, "comment": "EDR LSASS access alert" },
    { "techniqueID": "T1114.003", "score": 0, "comment": "No inbox-rule audit in SIEM" }
  ],
  "gradient": { "colors": ["#ff6666", "#ffe766", "#8ec843"], "minValue": 0, "maxValue": 3 }
}
```

- `"name"` — 레이어가 무엇을 언제 보여 주는지.
- `"domain": "enterprise-attack"` — Enterprise 매트릭스.
- `"versions"` — ID가 가리키는 ATT&CK 버전(그리고 도구와 파일 형식 버전). 이게 없으면 다음 버전이 나온 뒤 레이어의 뜻이 애매해집니다.
- `"techniques"` — 기법마다 한 항목. `techniqueID`, `score`(여기서는 0 = 범위 없음부터 3 = 시험을 마친 탐지까지), 점수를 설명하는 `comment`. 예를 들어 T1547.001은 "워크스테이션에만 Sysmon 13"이라 2점, T1114.003은 "SIEM에 받은편지함 규칙 감사 없음"이라 0점.
- `"gradient"` — 빨강(0)에서 노랑을 거쳐 초록(3)까지의 색. 공백이 눈에 확 들어옵니다.

빨간 칸은 **T1114.003 Email Forwarding Rule**이고, [앞 페이지의 공격 트리](diamond-attack-trees.md#attack-tree-example)가 이미 짚은 것입니다. 이게 헌팅 가설이 됩니다. *"KL-CAMP-01이 미지급금 팀 메일함을 장악했다면, 공급업체 메일을 전달하거나 숨기는 규칙을 만들었을 것이다."* 헌터는 메일 플랫폼 감사 로그에서 최근 90일 동안 미지급금 팀 메일함에 생긴 새 받은편지함 규칙을 찾습니다. 특히 외부로 전달하거나, "bank"나 "invoice"가 들어간 메시지를 잘 안 보는 폴더로 옮기는 규칙. 헌팅에서 무엇이 나오든 안 나오든 결과는 새 탐지이고, 그 칸은 초록이 됩니다. ATT&CK 매트릭스가 잘하는 IOC 없는 헌팅입니다. 지표가 아니라, 공격자가 쓸 수 있는 기법과 우리가 아는 공백에서 출발합니다.

## 언제 어떤 모델을 쓰나 { #when-each-model }

연장통이 다 찼으니, 언제 무엇을 꺼낼지 정리합니다.

| 상황 | 질문 | 모델 |
| --- | --- | --- |
| **분류(Triage)** | 어느 경보가 가장 위험한가? | 사이버 킬 체인 / 공격 생명 주기 — 각 공격이 얼마나 진행됐나? |
| **사고 대응** | 다음에 무엇을 하나? | 사고 대응 주기(PICERL) |
| | 무엇을, 어떻게 막나? | 고통의 피라미드 |
| **방어 전략 / 감사** | 빠진 통제가 무엇인가? | 위협 모델과 공격 트리 |
| **헌팅 / 분석 규칙 개발** | 아직 탐지 못 하는 것 중 무엇을 찾아야 하나? | MITRE ATT&CK |
| **위협 인텔리전스** | 이 많은 지표로 무엇을 하나? 바깥 정보를 어떻게 쓰나? | 세 수준, F3EAD, 인텔리전스 주기, 다이아몬드 모델 |
| **작전 속도** | 우리는 충분히 빠르고 유연한가? | OODA 루프 |

야간 근무 한 번을 짧게 따라가면 순서대로 나옵니다.

1. **분류.** 대기열에 피싱 클릭 경보, 인터넷에서 온 포트 스캔, KL-WS-0712의 C2 비컨 경보가 있습니다. 킬 체인으로 생각하면 비컨이 가장 많이 진행됐습니다(막히지 않은 활성 C2 채널). 그래서 먼저입니다. 지금 데이터가 나가고 있다는 낌새가 있다면 그게 모든 것보다 앞서지만요.
2. **사고 대응.** 사고가 선언됩니다. 준비와 식별은 끝났으니(탐지가 울렸고 범위를 확인 중) 사고 대응 주기는 다음이 **봉쇄**라고 말합니다. C2를 끊어 출혈을 멈춥니다. 프록시나 방화벽 차단, 네트워크·호스트 IPS 규칙, EDR 격리를 통한 호스트 방화벽 규칙. 예외는 표적 침입자를 일부러 지켜보며 기다리기로 결정한 경우이고, 이 가이드 뒤에서 다룹니다.
3. **무엇을 막을지.** 고통의 피라미드: 해시, IP, 도메인은 지금 막고(싸고 즉각적), 흔적·도구·행동 탐지는 탐지 엔지니어링으로 넘깁니다(오래감).
4. **위협 인텔리전스.** F3EAD의 활용 단계: LNK 메타데이터, 이메일, 타임라인을 거둬들이고, 다이아몬드 모델이 이 이벤트를 KL-CAMP-01과 잇습니다.
5. **헌팅.** ATT&CK 방어 범위가 받은편지함 규칙 공백을 보여 주고, 내일의 헌팅이 정해집니다.
6. **전략.** 대금 사기 공격 트리가 관리자의 "다음 통제는?" 질문에 대한 답을 갱신합니다.
7. **속도.** 그 모든 것 밑에 OODA 루프가 있습니다. 상황을 더 정확히 이해하고 더 빨리 적응하는 쪽이 이깁니다.

## 정신 모형이 왜 중요한가 — 그리고 왜 모두 틀렸나 { #why-models }

OODA 루프의 *방향 잡기(Orient)* 단계는 우리의 모형이 데이터를 만나는 곳입니다. 모형이 틀렸으면 더 열심히 해도 소용없습니다. 틀린 방향으로 더 빨리 방향을 잡을 뿐입니다. "가진 게 망치뿐이면 모든 게 못으로 보인다"는 말처럼, 킬 체인만 아는 분석가는 악성코드를 한 번도 쓰지 않은 내부자까지 모든 사건을 악성코드 일곱 단계에 억지로 넣습니다. 이 섹션의 목표는 둘이었습니다. 공격, 방어, 위협 인텔리전스에 대한 업계 표준 모델을 갖춰서 문제를 쪼개고 머리 밖에 적을 수 있게 하는 것([기억 페이지](../analyst-cognition/memory-experience.md)의 분해와 외부화). 그리고 OODA를 통해, 모델을 *많이* 갖는 게 *왜* 중요한지 보여 주는 것. 빠르게 바뀌는 싸움에서는 맞는 관점으로 가장 빨리 갈아탈 수 있는 쪽이 유리합니다.

그리고 통계학자 George Box에게서 온 마지막 경고. **모든 모델은 틀렸다. 그러나 일부는 쓸모 있다.** 우리 머리에는 한계가 있으니 단순하게 만들고(지각과 기억 섹션의 제한된 합리성), 단순하게 만든다는 건 세부를 뺀다는 뜻입니다. 이 섹션의 모델들이 삐걱거리는 예:

- 훔친 세션 토큰으로 하고 악성코드는 없는 클라우드 침입에는 킬 체인이 말하는 "설치"나 "무기화"가 없습니다.
- 고통의 피라미드는 해시가 약하다고 하지만, 손으로 만든 고유 도구의 해시를 동료 조직과 빠르게 공유하면 처음 며칠 동안은 헌팅에 여전히 값집니다.
- PICERL은 순서로 그려지지만, 실제 사건에서는 새 범위가 나타나면 제거 단계에서 식별 단계로 다시 돌아갑니다.

모델은 뼈대이자 출발점으로 쓰세요. 사건마다 미묘한 차이가 다르기 때문에, 어떤 그림을 외우는 것보다 분석적·비판적 사고 능력 — 다음 섹션의 주제 — 이 더 중요합니다.

## 2026년 관점 { #trends }

!!! success "[2026 현재] 지금도 그대로 유효"
    고통의 피라미드는 여전히 탐지 엔지니어링과 위협 헌팅에서 가장 많이 인용되는 모델 중 하나이고, 그 교훈 — 원자 지표만이 아니라 행동에 투자하라 — 은 현대 EDR과 코드로 관리하는 탐지(detection-as-code)의 바탕입니다. MITRE ATT&CK은 확고한 공통 언어입니다. EDR과 SIEM 업체는 탐지에 ATT&CK ID를 붙이고, 위협 인텔 보고서는 ATT&CK에 매핑하고, MITRE의 보안 제품 평가도 ATT&CK을 씁니다. YARA와 Sigma는 여전히 파일 탐지와 로그 탐지의 표준 공개 형식입니다. "모든 모델은 틀렸고 일부는 쓸모 있다"는 그 어느 때보다 맞는 말입니다.

!!! info "[변경됨] 바뀐 점"
    - **ATT&CK은 2020년대 초 자료 이후 많이 바뀌었다.** 버전 18(2025년 10월)은 기법마다 붙어 있던 데이터 출처 기반 탐지 설명을 *탐지 전략*과 *분석*으로 바꿨습니다. 버전 19(2026년 4월)는 Defense Evasion 전술을 없애고 그 기법들을 새 전술 둘, **Stealth**와 **Defense Impairment**로 나눴습니다. 옛 탐지와 보고서는 다시 매핑해야 합니다. 버전 20(2026년 10월)은 AI 시스템 악용 기법과 MFA 우회·아이덴티티 기법을 더했습니다. 클라우드는 이제 따로 떨어진 매트릭스가 아니라 Enterprise 영역 안의 플랫폼으로 다룹니다.
    - **피라미드 바닥은 공격자에게 더 싸졌다.** 자동 빌더, 피해자별 패킹, AI 도움을 받은 코드 변경 때문에 고유 해시가 기본이 됐습니다. 공격자는 C2와 준비 단계에 정상 클라우드·SaaS 서비스를 점점 더 씁니다(ATT&CK T1102 Web Service, T1567 Exfiltration Over Web Service). 그래서 "그들의" 도메인을 막는다는 게 우리 회사가 쓰는 서비스를 막는 일이 될 수도 있습니다. 옛 예제들이 자주 드는 유명한 무료 도메인 등록 업체는 2023년에 신규 등록을 멈췄지만, 싼 도메인과 무료 하위 도메인은 여전히 쉽게 구합니다.
    - **네트워크 흔적이 위층으로 올라갔다.** C2가 거의 다 TLS 안에 있으니, URI나 User-Agent 같은 흔적은 TLS 검사 없이는 안 보이는 경우가 많습니다. TLS와 HTTP 클라이언트 지문(JA3는 대체로 **JA4+** 계열에 자리를 내줌), 인증서 패턴, 비컨 주기가 더 많은 몫을 맡습니다.
    - **AI가 매핑을 돕는다.** SOC 코파일럿과 CTI 도구가 경보와 보고서의 ATT&CK 매핑을 자동으로 제안합니다. 쓸모 있지만, 없어졌거나 틀린 기법으로 매핑하는 게 알려진 실패 방식입니다. 확인하세요.

!!! warning "[주의] 옛 방식대로 하면 틀리거나 위험한 점"
    - **피라미드 바닥에서 멈추지 마세요.** 해시 하나, IP 하나 막고 사건을 닫으면, 공격자가 새 서버에서 새 빌드로 들키지 않고 돌아오는 게 거의 확실합니다.
    - **ATT&CK 범위를 최대로 올릴 점수로 다루지 마세요.** Navigator의 초록 칸은 규칙이 있다는 뜻일 뿐, 실제 변형에 울리는지, 잡음이 얼마나 많은지, 그 데이터 출처를 수집하기는 하는지 말해 주지 않습니다. 범위로 표시하기 전에 탐지를 시험하고(예: 공격 에뮬레이션이나 원자 단위 테스트), 위협 모델이 중요하다고 하는 기법부터 챙기세요.
    - **옛 ATT&CK 매핑을 그대로 다시 쓰지 마세요.** Defense Evasion(TA0005)이나 옛 기법 이름이 들어간 보고서, 규칙, 레이어는 현재 버전으로 다시 매핑해야 합니다. 어느 버전으로 매핑했는지 늘 적으세요.
    - **정상 클라우드 서비스를 공격자 도메인처럼 통째로 막지 마세요.** C2가 SaaS 플랫폼을 쓰면, 서비스 전체가 아니라 가능한 한 특정 테넌트, 버킷, URL 경로를 막거나 행동을 탐지하세요.

## 확인 문제 { #quiz }

### 문제 1

사고 중에 이런 것들이 있습니다. (a) 드로퍼의 SHA-256, (b) C2 도메인, (c) 비컨이 늘 300초마다 `/api/v2/ping`으로 64바이트를 POST한다는 사실, (d) 뮤텍스 이름 `Global\UpdSvcMtx`, (e) 공격자가 늘 LNK에서 Explorer가 숨긴 인코딩 PowerShell을 띄우게 해서 실행을 얻는다는 관찰. 각각을 고통의 피라미드에 놓고, 오늘 각각으로 무엇을 할지, 탐지 엔지니어링 시간은 어디에 쓸지 말하세요.

??? success "정답과 해설"
    (a) **해시 값** — 바닥. (b) **도메인 이름**. (c) **네트워크 흔적**. (d) **호스트 흔적**. (e) **TTP** — 꼭대기. ((c)와 (d)를 포함한 여러 문자열로 만든 YARA 규칙이라면 **도구** 단계 탐지가 됩니다.)

    오늘: (a)와 (b)는 바로 막고 — 싸고, 지금 C2를 멈추는 게 중요하니까 — 환경 전체에서 찾아봅니다. (c)와 (d)의 탐지를 배포합니다. 새 서버의 새 빌드도 잡습니다. 진짜 탐지 엔지니어링 시간은 (e)에 씁니다. 프로세스 생성(4688 / Sysmon 1, T1204.002, T1059.001, T1027)에 대한 행동 규칙을 만들고 정상 관리자 사용에 맞게 다듬습니다. 공격자의 다음 도구와 같은 수법을 쓰는 다른 행위자까지 잡는 건 이것뿐입니다.

### 문제 2

동료가 매트릭스의 80%가 초록인 Navigator 레이어를 보여 주며 SOC가 "80% 방어된다"고 합니다. 이게 오해일 수 있는 이유 셋을 들고, 대신 ATT&CK으로 다음 헌팅을 어떻게 계획할지 설명하세요.

??? success "정답과 해설"
    (1) 초록이 "실제 변형에 울리는 규칙"이 아니라 "규칙이 있음"일 수 있습니다. 시험하지 않은 탐지는 자주 실패합니다. (2) 데이터 출처의 현실을 반영하지 않을 수 있습니다. 그 로그를 모든 호스트에서 수집하지 않으면(예: 워크스테이션에만 Sysmon) 규칙은 쓸모없습니다. (3) 기법은 똑같지 않습니다. 잘 안 쓰이는 기법을 많이 덮고 우리 공격자가 실제로 쓰는 몇 개를 놓치면 *위험*의 80%가 아닙니다. 게다가 레이어가 옛 ATT&CK 버전으로 매핑돼 있을 수도 있습니다(예: v19 이후에도 Defense Evasion 사용).

    더 나은 방법: 위협 모델과 위협 인텔리전스에서 출발합니다(우리를 노릴 만한 공격자는 어떤 기법을 쓰나?). 레이어에서 그중 범위가 없거나 약한 것을 찾고, 하나에 대해 가설을 세우고("미지급금 메일함을 가졌다면 전달 규칙을 만들었을 것 — T1114.003"), 관련 로그에서 헌팅하고, 결과를 시험을 마친 탐지로 만듭니다. ATT&CK 버전을 적습니다.

### 문제 3

각 상황에 이 섹션에서 가장 쓸모 있는 모델을 고르고 이유를 말하세요. (a) 새 경보 12개에 분석가 한 명. (b) 방금 사고가 선언됐고 공격자의 C2가 살아 있다. (c) CISO가 내년에 어떤 보안 프로젝트에 돈을 쓸지 묻는다. (d) 헌팅 팀이 다음 분기 아이디어를 원한다. (e) 팀에 사건 다섯 개에서 나온 지표 300개가 있는데 무엇을 할지 모른다.

??? success "정답과 해설"
    (a) **킬 체인 / 공격 생명 주기** — 공격이 얼마나 진행됐는지로 경보를 줄 세웁니다. 활성 C2와 유출 낌새가 있는 것이 먼저입니다. (b) **사고 대응 주기**, 그다음 **고통의 피라미드** — 다음 단계는 봉쇄(프록시, 방화벽, IPS, 호스트 격리로 C2 끊기)이고, 피라미드는 싼 지표는 지금 막고 행동 단계 탐지를 길게 밀어붙이라고 알려 줍니다. (c) **위협 모델과 공격 트리** — 최악의 결과로 가는 덮이지 않은 경로를 가장 많이 없애는 통제를 고릅니다. (d) **MITRE ATT&CK** — 우리를 노릴 만한 공격자의 기법과 지금의 범위를 비교하고 공백을 헌팅합니다. (e) **위협 인텔리전스 모델** — 세 수준(누구에게 무엇이 필요한가), **F3EAD**(분석을 거쳐 탐지로 돌려보내기), **다이아몬드 모델**(사건들을 이어 같은 행위자 찾기). 그 모든 것 내내 **OODA 루프**가 방향 잡기의 정확성*과* 속도가 이긴다는 걸 상기시켜 줍니다. 그리고 어떤 모델도 모든 경우에 꼭 맞지는 않습니다.

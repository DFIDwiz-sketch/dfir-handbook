# 침해 발견 후 대응 { #intrusion-response }

!!! abstract "한 줄 요약"
    앞 섹션들은 공격자에게 눈치채이지 않고 분류하고, 조사하고, 찾아보는 법을 보여 줬습니다. 이 섹션은 침해가 **확인된** 순간을 다룹니다. 어떻게 대응할지 정하는 질문들 — 공격자가 얼마나 오래 안에 있었나(체류 시간), 어떤 종류의 침해인가, 백도어를 몇 개나 쥐고 있을까(단기·장기), 왜 우리 네트워크를 원하나, 지금 비즈니스 위험이 얼마나 큰가, 그들에 대해 우리가 실제로 무엇을 아나 — 그리고 "무시"부터 "전부 다시 구축"까지 대응 방식 고르기, 기회주의 공격과 표적 공격의 차이, 흔한 대응 실수, 대역 외 통신, 스스로 만드는 장애 피하기를 봅니다.

## 꼭 기억할 것 { #must-know }

1. 침해 확인은 결정의 시작이다. 격리 버튼에 손대기 전에 질문부터 한다 — 피해가 진행 중이 아니라면.
2. 체류 시간은 첫 경보가 아니라 믿을 만한 가장 이른 증거에서 나온다. 그리고 우리 로그는 공격이 시작되기 전에 끝날 수 있다.
3. 오래 있었을수록 발판이 더 많다고 예상하고, 범위 잡기에 며칠 쓰는 추가 위험은 더 작아진다.
4. 끈질긴 공격자는 시끄러운 단기 문과 조용한 장기 문을 둔다. 긴 기간으로 헌팅하고, 계정과 클라우드 ID를 포함한다.
5. 공격자에게 우리가 어떤 역할인지 묻는다: 전략적 목표, 전술적 디딤돌, 그냥 인프라.
6. 비즈니스 위험이 모든 걸 뒤집는다: 안전 시스템, 진행 중인 유출이나 파괴는 지금 행동하라는 뜻이다.
7. 아는 것을 킬 체인과 고통의 피라미드에 대 본다. 빈칸이 곧 조사 계획이다.

    RedLine Stealer — PowerShell 스크립트에서 net.tcp C2 정보 탈취까지¶

    사례 요약

    coolweathercoat.com 도메인의 윈도우 10 PC에서 사용자가 PowerShell 스크립트(mystery_file.ps1)를 실행했습니다. 스크립트는 공격자 서버에 "시작했다, 백신은 Windows Defender다"라고 보고하고, .jpg로 위장한 악성 실행 파일을 HTTPS로 받았습니다. 실행된 RedLine Stealer는 DNS 조회 없이 IP로 직접 TCP 12432 포트에 붙어, 서버가 내려 준 "훔칠 대상 목록"대로 정보를 모은 뒤 약 540KB를 한 번에 올려 보냈습니다. 화면 캡처, 시스템 정보, 프로세스 목록, Edge에 저장된 비밀번호, 문서 파일이 들어 있었어요. 캡처 전체가 36초밖에 안 되는 짧은 PCAP입니다.

    0단계 — 데이터 범위와 전체 그림¶

    목적: 데이터의 시작·끝, 크기, 내부 PC를 먼저 파악합니다.

    1단계 — DHCP로 IP, MAC, 호스트이름 찾기 (Q2~Q4)¶

    목적: PC가 IP를 받을 때 보내는 DHCP 요청에는 MAC 주소와 호스트이름이 들어 있습니다. 이 PCAP은 DHCP로 시작하니 가장 확실한 출처예요.

    쿼리:

    protocols == dhcp
    조각 뜻
    protocols Arkime가 알아낸 프로토콜 필드
    == dhcp DHCP 세션만

    SPI View → dhcp 섹션 → Load All. 중요한 필드는 dhcp.host(호스트이름), dhcp.mac(클라이언트 MAC), dhcp.classId(벤더 클래스)입니다. 세션을 펼치면 요청과 응답 내용이 다 보입니다.

    실제 결과:

    22:39:22.849  DHCP Request   0.0.0.0:68 → 255.255.255.255:67
              Client MAC        80:86:5b:ab:1e:c4
              Host Name (12)    DESKTOP-9PEA63H
              Client FQDN (81)  DESKTOP-9PEA63H.coolweathercoat.com
              Requested IP (50) 10.7.10.47
              Vendor class (60) MSFT 5.0

22:39:22.850  DHCP ACK       10.7.10.9:67 → 255.255.255.255:68
              Your IP           10.7.10.47
              Subnet mask       255.255.255.0
              Router            10.7.10.1
              DNS server        10.7.10.9
              Domain name       coolweathercoat.com

    결과 읽기:

    • IP 10.7.10.47, MAC 80:86:5b1e:c4, 호스트이름 DESKTOP-9PEA63H — Q2, Q3, Q4의 답입니다.
    • MSFT 5.0은 윈도우 2000 이후 모든 윈도우가 보내는 DHCP 벤더 클래스예요. 윈도우 PC라는 근거입니다.
    • DHCP 응답에서 네트워크 정보도 나옵니다. 대역 10.7.10.0/24(마스크 255.255.255.0), 게이트웨이 10.7.10.1, DNS와 DHCP 서버는 10.7.10.9, 도메인 coolweathercoat.com.
    • 교차 확인: 이 PC가 보낸 일반 패킷의 Src MAC도 80:86:5b:ab:1e:c4입니다. NetBIOS(137) 브로드캐스트에도 DESKTOP-9PEA63H와 도메인 COOLWEATHERCOAT가 나옵니다. 출처 두 곳이 같은 값을 주면 확실합니다.

    PC가 이미 IP를 갖고 있던 시점부터 캡처하면 DHCP가 없습니다. 그때는 NetBIOS(udp 137/138 브로드캐스트)의 이름, Kerberos의 $로 끝나는 cname(다음 단계), SMB 세션의 호스트 정보로 찾습니다.

    2단계 — DC와 사용자 계정 찾기 (Q5)¶

    목적: 도메인 컨트롤러(DC)의 이름과, 이 PC에 로그인한 사용자 계정을 찾습니다.

    DC 찾기 (DNS SRV)¶

    윈도우 PC는 로그인할 때 "이 도메인의 DC가 어디야?"를 DNS의 SRV 레코드로 물어봅니다.

    host.dns == _ldap._tcp.dc._msdcs.*
    조각 뜻
    host.dns DNS로 질의한 이름
    _ldap._tcp.dc._msdcs.* "DC의 LDAP 서비스는 어디?"라는 표준 질의. *는 뒤의 도메인 이름 아무거나

    실제 결과 (세션 상세의 DNS 응답):

    Query   _ldap._tcp.dc._msdcs.coolweathercoat.com  (SRV)
Answer  SRV  win-s3wt6lgqfvx.coolweathercoat.com
Query   win-s3wt6lgqfvx.coolweathercoat.com  (A)
Answer  10.7.10.9

    → DC는 10.7.10.9, 이름 WIN-S3WT6LGQFVX. 이름이 WIN- + 무작위 글자인 건 윈도우 서버를 설치하고 이름을 바꾸지 않았을 때의 기본 형식이에요.

    사용자 계정 찾기 (Kerberos)¶

    ip.src == 10.7.10.47 && protocols == krb5
    조각 뜻
    ip.src == 10.7.10.47 감염 의심 PC가 시작한 연결
    && 그리고
    protocols == krb5 Kerberos 세션만

    SPI View → krb5 → Load All (필드 이름만 보이면 필드 이름을 누르거나 Load All).

    실제 결과:

    cname   desktop-9pea63h$   rwalters
Realm   COOLWEATHERCOAT.COM
sname   krbtgt/COOLWEATHERCOAT.COM   ...

    결과 읽기:

    • 끝이 $인 desktop-9pea63h$는 컴퓨터 계정입니다. 1단계의 호스트이름과 같아요.
    • $가 없는 rwalters가 사용자 계정입니다. Q5의 답입니다.
    • 캡처 시작 직후(22:39:23~)에 Kerberos가 26번이나 나오는 것도 1단계의 해석과 맞습니다. PC가 켜지고 사용자가 로그인하는 장면이에요.

    티켓 기록:

    [251118 0017, Analyst] Identifying DC from DNS SRV and user account from Kerberos - Found

[251118 0017, Analyst] Query: host.dns == _ldap._tcp.dc._msdcs.* -> SRV win-s3wt6lgqfvx.coolweathercoat.com -> A 10.7.10.9 (DC).

    7단계 — C2 세션 읽기: 프로토콜과 흐름¶

    목적: 12432 세션이 어떤 프로토콜을 쓰고, 언제 무엇이 오갔는지 봅니다.

    ip.dst == 194.26.135.119 && port.dst == 12432

    세션을 펼칩니다. Arkime에는 이 프로토콜을 해석하는 파서가 없어서 Protocols에 tcp만 나오고 HTTP·TLS 같은 섹션이 없습니다. 아래쪽 패킷 내용(Source / Destination)을 ascii로 보면 됩니다. 길어서 Source Raw로 내려받아 CyberChef Strings로 보는 게 편해요.

    실제 결과 — PC가 처음 보낸 내용:

    결과 읽기:

    • net.tcp://로 시작하는 건 .NET의 WCF(Windows Communication Foundation) net.tcp 프로토콜입니다. HTTP 대신 TCP 위에서 SOAP 메시지를 이진(binary) 형식으로 주고받아요. 그래서 평문 HTTP처럼 깔끔하게 읽히지는 않지만, 문자열은 그대로 보입니다. RedLine은 .NET으로 만든 악성코드라서 이 방식을 씁니다.
    • http://tempuri.org/는 .NET 개발 도구가 이름 공간을 따로 정하지 않으면 넣는 기본 자리표시 주소입니다. 실제 웹사이트에 접속하는 게 아니에요. 정상 프로그램은 배포 전에 보통 바꾸기 때문에, 외부 IP와의 통신에서 tempuri.org가 보이면 대충 만든 .NET 프로그램(악성코드 포함)일 가능성이 큽니다.
    • MSValue1, MSValue2, MSValue3은 호출하는 함수 이름입니다. 의미를 숨기려고 이름을 바꿔 놨어요.
    • Authorization c75a6809…는 이 악성코드 빌드를 구분하는 키로 보입니다(추정). 같은 공격자의 다른 감염을 찾을 때 쓸 수 있는 지표예요.

    교훈¶

    • 짧은 PCAP일수록 "모르는 포트 하나"가 바로 보입니다. 포트 목록을 역할별로 나누면 정상 AD 통신 속에서 12432가 튀어나옵니다.
    • DHCP가 있으면 IP·MAC·호스트이름을 한 번에 얻습니다. 캡처가 DHCP로 시작하면 PC가 켜지는 장면부터 기록된 것입니다.
    • WindowsPowerShell User-Agent와 User-Agent 없는 요청은 둘 다 "사람이 아닌 프로그램"의 표시입니다.
    • 상태 200 + 본문 "404" 같은 앞뒤가 안 맞는 응답은 위장일 수 있습니다.
    • 정식 인증서(Let's Encrypt)라고 안전하지 않습니다. 판단은 맥락으로 합니다.
    • JA3 변화가 없다고 깨끗한 게 아닙니다. 이 사례는 페이로드 다운로드가 윈도우 서비스와 같은 JA3를 썼고, C2는 TLS조차 아니었습니다.
    • 업로드 ≫ 다운로드인 세션은 유출 후보 1순위입니다(databytes.src).
    • 암호화되지 않은 C2는 서버의 지시와 훔친 내용을 다 보여 줍니다. 서버가 내려 준 목록으로 "무엇을 노렸나"를, 업로드로 "무엇을 잃었나"를 나눠서 보고하세요.
    • 캡처 손실을 기록하세요. 빠진 조각 때문에 증거(화면 캡처)가 일부 깨졌다는 사실도 티켓에 남겨야 합니다.
